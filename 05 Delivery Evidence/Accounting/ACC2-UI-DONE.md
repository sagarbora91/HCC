## Stubbed names (`_contract-stubs-2.ts`) and the shapes assumed
Contract names kept exactly: `accGstMonth`, `accMonthLockBlocker`, `tdsDeducteeReport`, `tdsForBill` (stub `() => 0`, as the purchase lane stubs it), `tdsReceivableReport`, `expVendorAgeing`, `accCashGuard`, `accPartyRetireBlocker`; commands `ACC_MANUAL_SAVE / _DECIDE / _VOID`, `ACC_LOAN_ADD`, `EXP_VENDOR_PAY / _PAY_VOID / _RETURN`, `CHN_PAYOUT`, `DEPOSIT_APPLY`, `ACC_TDS_REMIT`, `ACC_GST_SETOFF`, `ACC_GST_PAY`, `ACC_STAT_REMIT`, `ACC_MONTH_LOCK / _LOCK_REQUEST / _UNLOCK`, `GRP_COMPANY_PAYMENT.tds`, `GRP_COMPANY_SAVE.active`, `CMP_PROFILE_SET` switches.
Names the contract does not give (invented; rename or provide in the real lanes): `accManualList(s)` (newest first, the slice), `accManualProblems(s,{date,voucherType,lines})` → `string[]` (the §2 guard messages), `accLoans(s)`, `accAssetsList(s)`, `accAssetsCsv(rows)`, `accMonthLockOf(s,month)`, `accGstHeads`, `tdsRateRows(s,date)`, `tdsDeducteeCsv(rows,period)`, `expVendorOpenBills(s,vendor)`, `expVendorAdvance`, `expVendorAllocate(s,vendor,amount)` (oldest first, opening balance as `{expense:'opening'}`), `expVendorPayments(s)`, `expVendorAgeingCsv`, `chnPayouts(s)`, `chnOpenReceivable(s,channel)`, `expPurchaseItcGuard(s,{category,itc,gstBps})` → message or `''` (DEC-143; should extend `expItcRefusal`), `CASH_GUARD_KEYS`.
Shapes:
- `ACCGstMonth = {month, output:{igst,cgst,sgst}, input:{igst,cgst,sgst}, rcm, tcs, cashLedger, setoff:{credit,against,amount}[], payable:{igst,cgst,sgst}, payableTotal, carried:{…}, posted?: voucherId}`. `accMonthLockBlocker` returns `string[]` (the screen also accepts a string).
- `ExpOpenBill = {expense, date, bill, amount (net of TDS), paid, open, ageDays}`; `ExpAgeingRow = {vendor,b0,b31,b61,b90,total,advance}`.
- `TdsRateRow = {section,label,oldSection,threshold,rateIndividual,rateOther (bps),from,source,caConfirm}`; `TdsDeducteeRow = {vendor,pan,section,taxable,tds,remitted}`; `TdsReceivableRow = {company,month,tds}`; `tdsDeducteeReport(s, 'YYYY-MM' | 'FY2026')`.
- `ACCCashGuardVerdict = {ok, code?:'CASH_LIMIT', refusal?, warning?, deductionLost?}`; input `{kind:'receipt'|'payment', party, amount, date, transport?}`.
- Payloads (all send `key`): `ACC_MANUAL_SAVE {id?,date,voucherType,narration,reference?,lines,template}` (**the contract's `type` field is sent as `voucherType`** — `type` is the command discriminator; coordinator ruling), `ACC_MANUAL_DECIDE {id,approve,reason?}`, `ACC_MANUAL_VOID {id,reason}`, `ACC_LOAN_ADD {code,name,lender,accountLast4?,kind:'secured'|'unsecured',note?}`, `EXP_VENDOR_PAY {vendor,amount,method,reference,date?,allocations}` (allocations always sent, may include `{expense:'opening'}`), `EXP_VENDOR_PAY_VOID {id,reason}`, `EXP_VENDOR_RETURN {expense,amount,gstPaise,reason}`, `CHN_PAYOUT {channel,date,statementRef,gross,commission,commissionGst,tcs,net,bank,bookings}` (`bank` = the bank account **code**, i.e. the part after `1030/`), `DEPOSIT_APPLY {booking,amount,source?:'opening'}`, `CHECKOUT {id, otaCredit?:true}`, `ACC_GST_SETOFF {month}`, `ACC_GST_PAY {month,amount,method,challan,date,rcm?:true}` (RCM payment = same command with `rcm:true`; the gst lane may prefer another name), `ACC_STAT_REMIT {kind,month,amount,method,challan,date}`, `ACC_MONTH_LOCK / _LOCK_REQUEST {month}`, `ACC_MONTH_UNLOCK {month,reason}`, `ACC_TDS_REMIT {month,section,amount,method,challan,date}`, `GRP_COMPANY_PAYMENT {…, tds?}`, `GRP_COMPANY_SAVE {…, active}` (sent for an existing company), `CMP_PROFILE_SET {…, gstOnAdvances, hotelDeductsTds, tdsDeductorType}` (Owner only), `HR_ADVANCE_ADD {…, funding}`, `EXPENSE {…, gstKind?, rcmBps?}` (`rcm` and `capital` are **not** sent: the category flags at posting decide).

The integrator's UI smoke should cover those.
- The Accountant has **no `payments` grant in the seed**; the contract names the Accountant for vendor payments / OTA payouts, so the UI gates on role (Owner / Manager with `payments`, Accountant with `reports`). The purchase / flows handlers must accept the Accountant the same way (grant `payments` to the Accountant role, or check the role).
- Retired-company filtering reads `(company as {active?:boolean}).active !== false`; `GRPCompany` has no `active` field yet (types file is the coordinator's) — add `active?: boolean` and `accPartyRetireBlocker` to the real lane.
- The company-payment form's default amount is the whole receivable; with a TDS entered the user lowers the amount (amount + TDS must equal what it clears). A "net of TDS" auto-split was not built.
- Category / vendor master screens do not yet expose the new flags (`rcm`, `rcmBps`, `capital`, `itcBlocked`, vendor `state`, `tdsSection`) — that is `money-master-specs.ts` (purchase lane); the form reads them from the masters.
- TDS rate-table editing stays in Master configuration (dated keys); the TDS tab is read-only.
- OTA payout bookings list = in-house / departed bookings of that channel not yet in a payout (display only).
