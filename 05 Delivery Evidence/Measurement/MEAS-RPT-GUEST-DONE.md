## Open items (assumptions the owner or integrator should confirm)
1. **Upsell target**: the contract lists no upsell-per-arrival target. Default Rs 50 (5000 paise) via `measTarget(s,'meas.target.upsellPerArrival')` (absent key = default). Needs a target row in `MEAS_TARGETS` (meas-settings file, not edited).
2. **Desk timing definitions in the prototype**: arrival-to-key = check-in instant to the first finished key job; bill-to-checkout = last bill-type audit entry by the same user in the 60 minutes before the CHECKOUT audit entry (prototype receipts carry a date only). The server uses real instants (`gst.stay.checked_in_utc`, `ops.key_job.finished_utc`, `bill.charge.posted_utc`, `pay.receipt.recorded_utc`). Desk user = the actor of the CHECKIN / CHECKOUT.
3. **Service recovery**: SLA comes from the complaint-category master (`gcatSlaDue`); "compensation without approval" = a recovery amount with no approval id. The entry says the compensation column sits "behind GSV-004": no such code exists in the matrix, so the report uses the money gate PERM-RPT-002 like every other money report.
4. **Repeat loyalty**: the permission is PERM-RPT-001 (the matrix has no PERM-CRM row; entry says PERM-CRM). The "3+ stay guests (name, last stay, mobile)" column is one text column in the entry; it shows the name only (GuestName mask, rule V); last stay and mobile are not shown. Server groups customers by the last 10 digits of the mobile; the loyalty tag join uses that same key, while `meas.customer_preference.customer_key` may hold the Customer-360 key: if they differ the tag column stays empty on the server (check on the PC with real data). Legacy (`lgc`) stays are not counted in "seen before" on either side yet.
5. **Day-use sold** is always 0 on the server (`gst.stay` requires departure > arrival); the prototype counts arrival = departure.
6. **Survey response rate** = surveys / stays that left in the month (with the room-type and channel filters).
