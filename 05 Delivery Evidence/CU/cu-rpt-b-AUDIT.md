## Findings

1. **FIX: "Deposits out" has the opposite sign to the prototype.** `08 Production/src/Hcc.Reporting/Reports/CuB/ReceiptsDepositsReport.cs` lines 238 and 246 (`Kind(day, ReceiptKind.DepositReturn)` / `Kind(receipts, ReceiptKind.DepositReturn)`) put a deposit return as a positive amount. The prototype builds the column from `receiptRow`, which negates `refund` and `deposit-return` (`03 Prototype/src/domain/streams/closing.ts` line 324), so `depositsOut` and the `deposit-out` total are negative (`tests/stream-f.mjs` line 191 asserts `deposit-out` = -50000; `closing.ts` line 183 flips it with `0 - v('receipts','deposit-out')` for the closing record). Same report id, same column, opposite sign: a ₹100 return shows `-100.00` in the prototype and `100.00` on the server. Right: `depositsOut` = `-Σ deposit-return` per day and in the total row (the second block is unaffected), and the test `ReceiptsDepositsReportTests.Tender_columns_follow_the_master_and_figures_are_exact_to_the_paisa` (lines 164 and 167, `10000L`) changed to `-10000L` so it fails on the current code. If the owner prefers positive returns, that is a ruling on both sides, not a server-only change.

2. **Note: order of unlisted tenders.** `ReceiptsDepositsReport.cs` line 219 appends tenders that are not in the master in ordinal order; the prototype `reportTenders` (closing.ts line 317) appends them in first-seen order. Only the column order differs, and only when two or more unlisted tenders occur in the range. Acceptable; say so in the DONE file or order by first receipt id.

3. **Note: empty master fallback.** `ReceiptsDepositsReport.cs` line 217 / `RestDaySummaryReport.cs` line 342 fall back to the seed tender lists when the master has no desk / POS method; the prototype would show no fixed tender columns. Unreachable on a set-up property; harmless.

4. **Note (DONE file wording): occupancy is stay-based on both sides.** DONE "Defaults used 2" and "Open questions" say the prototype counts booking intervals and the server stay intervals. The prototype counts In house / Departed bookings over `[arrival, departure)` (`reportStaysOn`), and its CHECKOUT refuses a check-out until every night up to `departure` has a room line (`handlers/folio.ts` line 399), so an early departure is a shortened stay first. The server's `ReportStay.End` (early check-out date) is the same figure in practice. No owner ruling is needed; the DONE text overstates a difference. Day use cannot occur (`CK_stay_dates departure > arrival`), no-shows / cancellations have no `gst.stay` row and are excluded on both sides, a room move is one stay (one night counted), out-of-order = `inv.v_room_block_effective` + `ops.room_block` (both block sources), split folios A–D do not double count (each charge belongs to one folio; one stay per reservation, `UQ_stay_reservation`). Room revenue = `kind = room` lines by service date on both sides, so a correction / rate re-post reversal (kind correction / 'adjustment') stays out of room revenue on both sides, exactly as the daily pack; this is the prototype's own definition, not a lane defect.

5. **Note: receipts sources equal the prototype's inputs.** `SqlReportSource` reads `pay.receipt` joined through `bill.folio` to `inv.reservation`: stay folios only (all four letters A–D), so hall receipts, counter bills and LF Udhaar desk payments are out, as in the prototype tab (which reads `s.bookings[].receipts` only). Kinds: payments − refunds per tender (refund sign correct), deposits in, company credit = `company-credit` only (OTA credit and guest credit out), as the prototype. Tender = the snapshot name stored on the receipt, as the prototype's `r.method`: after a rename the old name gets its own column, on both sides. Deposits held now: Σ deposit − deposit-return − deposit-apply (except the opening-advance tender `Opening advance applied` = prototype `depositSource:'opening'`) over every folio of the property, point in time, matching `selectors.ts` line 33 and `totals(b).deposit`. Bank deposits / till transfers are not part of this prototype report (they belong to the cash book of lane rpt-a).

6. **Note: rest.day-summary equals posDaySummary.** Outlets from settled `pos.bill` snapshots (net / tax / total) by outlet, all outlets total, open checks by outlet; settlement = master POS methods in order, then "Posted to room folios" (bills with no tender = folio settlement, as `mode==='folio'`), then other names found: same rows as the prototype's `byMode`.
