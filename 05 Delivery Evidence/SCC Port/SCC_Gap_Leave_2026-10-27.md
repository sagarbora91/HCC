## SCC behaviour that looks like a bug: port it, but ask the owner

- **Q1 Default week-off is Saturday + Sunday** (`WEEKOFF_DEFAULT [0,6]`, L99). For a hotel that runs 7 days, every Saturday and Sunday leave date would be silently skipped. SCC's own help text says to untick both for a 7-day trading week. Port the setting, but which default for HCC?
- **Q2 `MAX_SHIFT = 4` can never apply.** `MAX_DAY = 3` binds first, so "Max 4 per shift → max 8 people" (L536) is wrong. The day view then shows "3 / 4 · 1 slot(s) remaining" on a day that is already full (L962-986). Keep both constants as SCC has them?
- **Q3 Store holidays ("marker only", H830) still raise the "leave is discouraged" warning**, because the blackout check does not filter by kind (L1238, L1363).
- **Q4 The balance ignores pending leave and approval checks nothing.** Several pending requests can together exceed the quota and all be approved (L207-220, L280-296). The over-quota warning can also be overridden by the person recording it (L1350).
- **Q5 Requested days include dates later skipped** as duplicate or full (L1256-1268 vs L1383-1387), which can give false "EXCEEDS" warnings.
- **Q6 No access control on decisions.** Anyone can approve, including their own leave, and the record names the nominated approver (or 'Owner') as decider, not the person who clicked (L286-288). Anyone can also record leave for anyone and change entitlements, caps and blackouts.
- **Q7 Hard delete of any leave**, including approved leave already paid, with no audit trail (L1452-1459). The read-only guard looks at the **viewed** date, not the leave date, so back-dated leave can be created or deleted while viewing today (L585-598, L1321-1340).
- **Q8 Import is stricter than the screen.** Import skips any second record for the same name on a date (L1942); the screen allows AM + PM halves (L1383).
- **Q9 Backup and Clear All are inconsistent.** The JSON backup omits store caps and blackouts (L1974-1977). Clear All keeps them although it says "All data cleared" (L2012-2026).
- **Q10 Leave is keyed by name** (case-insensitive). Renaming staff orphans their history and overrides; two staff with the same name merge. HCC keys by staff ID: recommend keeping that.
- **Q11 The 7-day strip counts records, not people.** AM + PM of one person = "2 on leave" and availability is understated (L900, L926).
- **Q12 A request across 31 March is checked only against the start date's FY quota** (L1345), though usage is later booked by date.
- **Q13 The calendar cannot go before May 2026** (L603-604). That would hide HCC's FY26 history.
- **Q14 The approvals note says decisions must be made within 7 days** of the leave date because the shell's cross-module sync only scans that window. This is not in leave.js, and HCC reads leave directly, so there is nothing to port. Confirm.
- **Q15 Entitlement defaults: a cleared field saves 0** (L351), so the quota silently becomes 0. Fractions are allowed and there is no maximum.
- **Q16 Date keys come from UTC** `toISOString` on dates parsed as UTC (L1236-1237, L1262-1263, L1360-1362, L1380). This is correct only in time zones at or east of UTC, such as IST. The server must use local `DateOnly`.
- **Q17 What does a "store" become in a single-property hotel** (per-store caps #30, blackout scope #31, staffing-strip "Short:")? The property, or departments? And should HCC's blocking department cap (default 2) go, given SCC's single 3/day cap?
- **Q18 Approver choices:** SCC uses the Owner plus active "Store Manager" staff. Is HCC's equivalent the Owner plus Manager-role users?
- **HCC-only rules for keep-or-remove** (#11, 14, 17, 18, 21, 22, 36, 38, 39, 42, 43, 44, 45, 46, 62, 64). Most are controls HCC added: no self-approval, Owner-only settings, business-date floor, attendance link. A strict port removes them, and #18, #36 and #62 weaken security. Recommend an explicit owner decision per item. Separately, HCC's correction balance check ignores carry-forward (st:660; SC:68): an HCC bug that disappears if carry-forward is removed.
