The mocked tests could not catch it because they replace the probe completely. The other FIX items are security regressions against ETP's proven code, or a wrong exit code. The design of the adopt path is sound.

## (a) Adopt path safety: confirmed, with notes
In the adopt branch the only commands that touch the instance are `Get-Service`, `Start-Service` (lines 309-311, only when `Status -ne 'Running'`) and the probe. The probe is two `SELECT`s: `IS_SRVROLEMEMBER`, `SERVERPROPERTY`, `sys.dm_server_registry`. The script contains no `Restart-Service`, `Set-Service`, `Stop-Service`, `ALTER`, `sp_configure`, `CREATE LOGIN`, `CREATE DATABASE` or setup.exe call on that branch. The engine media is never part of the adopt branch's roles (`Get-HccSqlBootstrapPlan`, lines 80-82, adds `engine` only for Install). The only other writes on the PC are ODBC 17 and sqlcmd MSIs, and only when the PC has no sqlcmd at all. Those are client tools, not instance changes.

Starting a stopped service is acceptable. HCC cannot work without it, no setting changes, and its StartType stays as it was. A Disabled or Paused service makes `Start-Service` throw, which ends in exit 1, so the conservative outcome holds. See N1 for the leftover risk.

## (b) Mixed mode or TCP on an adopted instance accepted with a warning: acceptable, with conditions (N2)
`HccHosting.cs` line 71 governs HCC's own connection string (Integrated Security only). That rule still holds on a mixed-mode instance: HCC never uses a SQL login. Refusing the instance, as ETP does, would block HCC on a hotel PC where ETP or another program set the instance up. Fixing the instance would break rule §4.2 ("never reconfigure"). So warn-only is the right default for a shared instance.

The risk is real, though. Mixed mode **plus** TCP on means a network-reachable SQL-login surface (for example `sa`) in front of databases that will hold guest ID numbers. Conditions are in N2.

## (c) Install path: switches correct; exit-code ordering wrong (FIX 2); scratch folder (FIX 3)
- Switches (line 110-112) are exactly ETP's proven command line from `Get-EtpSqlEngineSetupArguments`, all of them documented setup parameters: `/ACTION=Install /QUIET /IACCEPTSQLSERVERLICENSETERMS /FEATURES=SQLENGINE /INSTANCENAME=SQLEXPRESS /SQLSYSADMINACCOUNTS=BUILTIN\Administrators /ADDCURRENTUSERASSQLADMIN=False /SQLCOLLATION=Latin1_General_CI_AS /TCPENABLED=0 /NPENABLED=0 /UPDATEENABLED=0`. Leaving out SECURITYMODE gives Windows authentication only.
- Collation: HCC's migrations use an explicit `COLLATE Latin1_General_BIN` / `BIN2` / `DATABASE_DEFAULT` wherever it matters. INSTALL.md (step 1, "default settings") and the tests assume no particular server collation. `Latin1_General_CI_AS` is ETP's choice for the same shared instance, and SQL setup's default for a non-en-US Windows locale. It is a good choice: an en-US PC would otherwise get `SQL_Latin1_General_CP1_CI_AS`. Nothing in the repo conflicts with it.
- Exit codes: extractor non-zero means throw. setup 3010 sets restart-needed, any other non-zero throws with Summary.txt named. msiexec 3010 sets restart-needed, any other non-zero throws. The catch logs and returns 1. This is correct, except for the ordering in FIX 2.
- `/X:` goes to a guid folder (no spaces) under `%ProgramData%\HCC\SqlSetup` and is removed in `finally` (line 251). The ACL is not set atomically: see FIX 3.

## (d) Media integrity
- The manifest is read from `$PSScriptRoot` (line 281), never from the media folder. File names are restricted to `^[A-Za-z0-9._-]{1,80}$` (no traversal). Every needed file is hashed before the first process starts (lines 296-304), and a link file is refused. Good.
- Gaps: only the folder's ACL is checked. The files' own ACLs, the folder's owner and whether the folder itself is a link are not checked. The MSIs are hashed and then run minutes later, after the engine install. Together these leave a time-of-check / time-of-use window: a file with its own writable ACE can be swapped after it was hashed. The helper also duplicates `Test-HccAdminOnlyWritable` from Hcc-Common (rule 7). See FIX 4.
- The manifest's `bytes` field is never used (N6).

## (e) Restart-pending, -PlanOnly, 5.1, StrictMode, quoting
- Keys checked: CBS `RebootPending`, WU `Auto Update\RebootRequired`, `Session Manager\PendingFileRenameOperations`. They are read only when an engine install is wanted. The "empty list counted as one reason" bug is really fixed: line 288 wraps the result in `@()`. I confirmed that an empty array bound to `[string[]]` gives Count 0 under 5.1 and 7. The test mock returns `@()` the same way the real function does (it unrolls to nothing), so the test covers it. False positives: see N5.
- `-PlanOnly` and `-WhatIf` (line 341) change nothing: the log is forced to '' (line 278), the administrator check and every process, service and probe step come after the `return 0` on line 305. Confirmed by real runs (above). Only reads happen: the service list, the registry, the sqlcmd path, and media hashing when media is given.
- 5.1: no `&&`, `||`, ternary, `??`, `-Parallel` or `?.`. `::new()` and `Get-ChildItem -Depth` are fine on 5.1. The script runs under 5.1 and 7.
- StrictMode: Latest is set again after Hcc-Common (line 34). `$svc.Status` is only reached when `$svc` is set. The `[0]` indexing in lines 232 and 264 is safe because the media check ran first. The `$Matches` reuse is FIX 1.
- Quoting: `Start-HccSetupProcess` (ETP's quoting) puts quotes around any argument with whitespace. The msiexec `/i <path under C:\Program Files\HCC\...>` call is quoted. `-FilePath` handles spaces. `/X:` has no spaces by construction. The probe query has no double quotes. OK.

## (f) Tests
The 18 checks assert real decisions: call order, nothing run before the media is accepted, exit codes 0, 1 and 2, no log file in a plan, the setup switches. What they miss is the parsing of real sqlcmd output (FIX 1), because `Invoke-HccSqlProbe` is replaced as a whole, and the WARN paths for mixed mode and TCP. See FIX 6 and N4.

## FIX list
1. **`08 Production/deployment/windows/Bootstrap-HccSql.ps1`, lines 211-213 (blocking).** After `$text -match 'HCC_PROBE:(\d+)\|(\d+)\|(\d+)'`, line 212 runs `$text -match 'HCC_TCP:(\d+)'`, which **replaces `$Matches`**. Line 213 then reads `$Matches[1..3]` from the TCP match. With realistic output (`HCC_PROBE:1|17|1` and `HCC_TCP:0`) the result was `IsSysadmin=False, MajorVersion=0, WindowsOnly=False` under both 5.1 and 7. Line 326 then throws "SQL Server 0 is too old", so **every real adopt and every fresh install exits 1**. The HCC_TCP row is always present for a sysadmin, because Express has the `SuperSocketNetLib\Tcp` `Enabled` value. Right: copy the three PROBE groups into locals straight after the first match, then do the TCP match. Better still, move the parsing into a pure function (`ConvertFrom-HccSqlProbeOutput -Text`) that the tests can call with real sample output.
2. **`Bootstrap-HccSql.ps1`, lines 247 / 318 / 325 / 331.** When setup or an MSI returned 3010, the probe still runs before the restart flag is looked at. If the engine or the driver cannot be used until Windows restarts, the probe throws and the script returns **1 (failed) instead of 2 (restart, then `-Resume`)**. Right: if `$needRestart` is set and the probe (or the sqlcmd lookup) fails, log it and return 2. Only a probe that succeeded may go on to the version and sysadmin checks.
3. **`Bootstrap-HccSql.ps1`, lines 173-185 (`New-HccProtectedScratchDirectory`).** The folder is first created with `New-Item -Force`, and its parents `HCC` and `HCC\SqlSetup` are created with the inherited `%ProgramData%` ACL, where Users may create files and folders. Only then does `Set-Acl` protect the folder, and the owner is not set. For that moment a non-administrator can plant an object in the folder (CREATOR OWNER gives them full control of it, and it stays theirs after `Set-Acl`), and the extracted `setup.exe` then runs with the administrator's full token. This is a regression against ETP's `New-EtpProtectedDirectory`. Right, as in ETP: create the folder in one step with its security (`[IO.Directory]::CreateDirectory($path, $sec)` on 5.1, `[IO.FileSystemAclExtensions]::CreateDirectory($sec, $path)` on 7), with the owner set to Administrators and inheritance off. Refuse if it already exists, then check it afterwards. Alternatively, protect `HCC\SqlSetup` first with the existing `Set-HccProtectedDirectory` and refuse a parent that is a link.
4. **`Bootstrap-HccSql.ps1`, lines 157-171 and 301 (`Test-HccPathAdminOnly`).** Only the folder's ACL is checked. Not checked: (a) each media file's own ACL (ETP: "a protected directory can still contain an explicitly writable child file"); (b) the folder's owner (an owner who is not an administrator can rewrite the ACL); (c) whether the folder or a parent is a link or junction. Any non-administrator S-1-5-80-* service SID is also accepted. Because the MSIs are hashed long before they run, (a) is a real time-of-check / time-of-use gap. The helper also copies the existing `Test-HccAdminOnlyWritable` (Hcc-Common.ps1 line 299), against rule 7. Right: call `Test-HccAdminOnlyWritable -Path $MediaDir -Extensions '.exe','.msi'`, add an owner check (SYSTEM, Administrators or TrustedInstaller), refuse a media folder that is a reparse point, and hash each file again just before `Start-HccSetupProcess` runs it (cheap for the 2-4 MB MSIs). For the 750 MB engine the gap is only the log writes, provided (a) and (b) hold.
5. **`Bootstrap-HccSql.ps1`, lines 151-152 (`Get-HccSqlcmdPath`).** The fallback runs any `sqlcmd.exe` found on PATH, elevated, without checking that its folder is protected. A user-writable PATH folder (for example a per-user tools folder) becomes an elevation path. ETP's `Resolve-EtpSqlCmd` returns only a candidate that passes `Assert-EtpProtectedInstall`. It also notes that go-sqlcmd resolves `.\SQLEXPRESS` over named pipes, which are off here, so a go-sqlcmd on PATH would fail the probe anyway. Right: either drop the PATH fallback or accept a candidate only when `Test-HccAdminOnlyWritable` returns nothing for its folder and its exe, in the same order as ETP (ODBC 17 tools, then 18, both under Program Files).
6. **`tests/Test-HccDeployment.ps1`, INST-SQL block.** Add, with no real SQL: (a) a check of the probe parser on real-looking output (`HCC_PROBE:1|17|1` plus `HCC_TCP:0`, plus `HCC_TCP:1` and `HCC_PROBE:1|17|0` for the two WARN lines, plus not-sysadmin output with no TCP line). It should fail on today's code and pass after FIX 1. (b) Setup returns 3010 and the probe then throws: expect 2. (c) After FIX 3, assert that `New-HccProtectedScratchDirectory` is built from a security object passed at creation. That can be a pure helper returning the `DirectorySecurity`, with its SDDL checked.

## Notes (no change required for PASS; for the orchestrator or the owner)
- N1 Adopt: after starting a stopped instance, log its StartType (read only) and warn plainly if it is not Automatic. HCC's service will otherwise lose its database after every reboot. Do not change it. A Disabled service should give a plain sentence ("SQL Server is switched off on this PC; ask whoever set it up"), not the `Start-Service` exception text.
- N2 Mixed mode and TCP warn-only: (1) the orchestrator (lane `server`) must copy the WARN lines into the final summary on screen, not only the log. (2) When **both** are on, say so as one stronger warning naming the risk (SQL logins reachable over the network next to guest data). (3) Keep the owner question in the DONE file open; I recommend the owner confirm warn-only for Trial and decide for Production. (4) For parity with ETP, also report read only (not refuse) named pipes on and the list of other Windows sysadmin members, so the owner knows who can read the HCC databases.
- N3 UseExisting on a PC without sqlcmd needs `-MediaDir` with the two client MSIs. Lane `server` ships SQL media "only when the task is selected", so it must ship at least `msodbcsql17.msi` and `MsSqlCmdLnUtils.msi` in UseExisting mode too, or the wizard must say that sqlcmd is needed.
- N4 Test isolation: dot-sourcing `Bootstrap-HccSql.ps1` into the test script leaves `Set-StrictMode -Version Latest`, `$ErrorActionPreference='Stop'` and the mock functions (`Test-HccAdministrator`, `Get-HccSqlcmdPath`, ...) in the test script's scope. When the `server` and `client` blocks are merged after this one, they will run under those settings and mocks. The integrator should restore the previous StrictMode and EAP at `# /INST-SQL`, or the lane should wrap the block in `& { ... }`.
- N5 `PendingFileRenameOperations` is often non-empty on a working PC (5 entries on this dev PC; antivirus, OneDrive, drivers). SQL setup's own RebootRequiredCheck looks at it too, so refusing is consistent. But when entries come back after the restart, the owner gets exit 2 again and again. Log the count, and on a `-Resume` where only this reason remains, say plainly which program keeps adding entries, or point to INSTALL.md.
- N6 The manifest `bytes` is unused. A size check before hashing would make a wrong file fail faster and with a clearer message. Optional.
- N7 `Get-HccInstalledOdbcDrivers` (lines 136-140) lists value names and does not check that the value is `Installed`, unlike ETP. This is harmless in practice: at worst it skips installing ODBC 17, and then the sqlcmd MSI fails loudly with 26010.
- N8 The Summary.txt hint (line 248) has a `<version>` placeholder. Naming the folder actually found under `Setup Bootstrap\Log` would help the owner.
- N9 Licence sentence for the wizard (DONE file) is exactly ETP's task text: OK.
