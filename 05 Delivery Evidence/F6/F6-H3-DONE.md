## Deviations from the contract
- **Soft hold expiry** is stored as its last business date (`soft_until_utc` = that date at 00:00) and compared with the business date, like the prototype's simulated clock; a real-time compare would expire holds at once in any test hotel whose business date lags the clock.
- **Lost reasons** on the server are the contract's six ids in `HallLostReasons` (code); H2's `hall.lost_reason` table replaces the list when it merges. Menus / T&C templates have no server read yet (H2 tables 4330–4344), so `hall-menu` writes stay prototype-only (mapper lists them as unmapped).
- **Room block on the server** is not built (needs the groups command inside the accept transaction); the prototype has it. The event still carries `block_id` (column from 4300).
- `Booking.hallEventId` is declared by the setup commit but not yet written when a booking is picked from an event block.
- Event-day extras can only be added at Close and bill (as H1); actual plates are entered there too.
- `tests/check-phone-hall.mjs` of the contract is `tools/check-phone-hall.mjs` (by hand, like `check-phone-lf.mjs`); no `Hcc.Integration.Tests/HallGoldenTests.cs`: the golden stays in `Hcc.Hall.Tests` (H1) through the real accounting consumer.
- `HallEvent.creditNote` / `HallCreditNote` added to `hall.ts` (optional field), `hall:credit-note` source added to `hallAccSources`.
