Hours = mapper + any missing server endpoint + test, for a developer who knows the codebase.

Spec citations: `02 Planning/HCC_Business_Workflow_Spec_v1.md` (WF-*). Areas the M0 spec does not cover (groups, POS, yield, assistant, documents, compliance, import) are cited from the Wave-4 scope in `02 Planning/agents/W4_Briefs.md` (W4-n) and, for areas 13-26, from `HCC_Implementation_Backlog.md` "Not in prototype backlog".

## 0. Headline

- **Two gaps block go-live.** Neither is in A2's unmapped or absent lists. Both are server-only routes that no client sends (A2 section D2):

I rate it Medium: it becomes Blocks go-live only if the CA's answer changes a seed value before the first day.

Day close refuses while any shift is open or awaiting a decision. The prototype's `SHIFT_CLOSE` path is dispatched by no screen, so production can never reach it.
- **All 25 unmapped or absent prototype commands** come out as **0 Blocks go-live / 8 Workaround exists / 17 Not needed**. The one real trap among them is group blocks: production can create a block but cannot pick up, release or cancel it.
- **No mapper targets a missing server command** (A2 D1: 172 of 172 found). Under the brief's rule, that means no High of that kind.

## (d) The two verdicts asked for

### (d1) A02-02: can the Owner change GST rates from the production app? **No (confirmed by code reading, not run).**

1. **What the screen offers.** Master configuration › Money and tax lists the GST keys from the client registry, `gstDefs` (`03 Prototype/src/domain/streams/config.ts:569-576`, registered at `:490`). The keys are `type:'percent'` / `'money'` / `'boolean'`, not `'fixed'`, so the client marks them editable (`config.ts:137,143`). The setting sheet therefore shows the editor and the Save button to whoever `cfgCanChange` allows, which is the Owner (`features/admin/config/SettingSheet.tsx:54,68`). Save dispatches `SETTING_SET` (`SettingSheet.tsx:42`).
2. **What the client sends.** The only `SETTING_SET` mapper always sends `SetSetting {key, value, effectiveFrom, reason, expectedVersion}` (`03 Prototype/src/clients/sync/admin.ts:257-263`). Its precheck blocks only the old `taxBps` key (`admin.ts:258`). No file under `03 Prototype/src` sends `SetGstSetting` or `WithdrawGstSetting`, or reads `GET /tax/gst` (0 files each, `evidence/A02b/greps.txt`).
3. **What the server refuses.** The GST group in the server's settings registry is `SettingType.Fixed`, `Editable = false` (`08 Production/src/Hcc.Application/Tax/GstSettings.cs:14-21`). `SetSettingAsync` throws `Validation(NotConfigurable)` for a non-editable key (`Hcc.Application/Configuration/ConfigurationService.cs:42-43`). The message the Owner sees is "This setting is not configurable." (`Hcc.Domain/Configuration/SettingRules.cs:42`). The only edit path is `POST /commands/SetGstSetting` / `WithdrawGstSetting` (`Hcc.Api/Endpoints/TaxEndpoints.cs:33-36`), handled by `GstMasterService.SetAsync` / `WithdrawAsync` (`Hcc.Application/Tax/GstMasterService.cs:24-75`). Both require `PERM-ADM-003`, Owner only (`Tax/TaxPorts.cs:11`). They need a **required** reason, an integer value, and for withdraw a `versionId` that only `GET /tax/gst` returns (`Hcc.Contracts/Tax/TaxContracts.cs:7,10`).
4. **Second effect: the displayed rates are not the server's.** `GET /configuration/values` skips `Fixed` settings (`Hcc.Application/Configuration/ConfigurationQueries.cs:149`), so no `gst.*` value reaches `configX`. The screen and `gstMasterSummary` (`mobile/admin/Settings.tsx:74`) show the client's seed (`gstSeedOn`, `config.ts:571`). If someone changes the GST master through the API, the app keeps showing the old seed while the server posts at the new rate. The server-side tax itself is not affected: postings resolve the rate from `tax.gst_setting_version` (`TaxEndpoints.cs:18-25`).
5. **Severity.** Medium. Invoices are taxed by the server's dated master, which is right. The control is missing, there is a manual workaround (an API call by a technician), and the screen misleads. It **becomes Blocks go-live** if the CA's answer (DEC-069 "illustrative - CA to confirm") changes any seed value before the first day, because the hotel then has no supported way to apply it. Fix: 8 h (ranked list, rank 3). Also correct the `TAX_SCHEDULE` reason at `admin.ts:281`.

### (d2) `SHIFT_CLOSE` absent: does it matter? **No.**

- **How a shift ends on the server.** `SubmitShiftCount` (`Hcc.Api/Endpoints/PaymentsEndpoints.cs:16`) → `CashierService.SubmitShiftCountAsync`:
  - **Exact count:** the shift is set to `Closed` in the same command (`Hcc.Application/Payments/CashierService.cs:109-113`).
  - **Count with a difference:** a reason is required, an approval is created and the shift becomes `Submitted` (`:115-124`). A different user with `PERM-SHF-002` decides it through `DecideApproval` → `DecideCashDifferenceAsync`. Approve sets `Closed`; reject reopens the shift for a recount (`CashierService.cs:191-217`; self-approval refused at `:200`).
- **Day close does not close shifts. It refuses while any shift is open or submitted:** check "Cash shifts reconciled" (`Hcc.Domain/Closing/CloseRules.cs:112-115`, blocking set `:83`, run in `ClosingService.CashStepAsync` `Hcc.Application/Closing/ClosingService.cs:234-237`).
- **The next shift.** It is opened by `OpenShift`: from the Cashier screen (`SHIFT_OPEN`, `clients/sync/cashier.ts:16-22`) or automatically by the client after a completed day close (`clients/sync/closing.ts:31-40`). The float is carried from the last counted close (`CashierService.cs:55-63`).
- **The client sends this path.** `SHIFT_SUBMIT` → `SubmitShiftCount` (`clients/sync/money.ts:323-332`) and `SHIFT_DIFFERENCE_DECIDE` → `DecideApproval` (`money.ts:333`). Both are dispatched from `features/closing/ShiftCount.tsx:22` and `mobile/money/Cashier.tsx` / `mobile/money/logic.ts:84`.
- **The prototype's `SHIFT_CLOSE` path is unreachable in production.** It lives only in `services/mock/commands.ts:150` and `services/mock/handlers/closing.ts:49-54`: an exact-count close by close-permission users, which `SHIFT_SUBMIT` with a zero difference duplicates. No file under `features/`, `mobile/` or `app/` dispatches it (0 hits, `evidence/A02b/greps.txt`; A2 B3). Nothing to map. Listing it in `closing.ts` `unmapped` with the reason "superseded by SHIFT_SUBMIT" removes the "absent" label (0.25 h, in A02b-10).
- Related, not this agent's area: E2E2 N10 (a cash refund executed with no open shift on 28 Oct). `RequireOpenShiftAsync` (`CashierService.cs:164-171`) is the guard for receipts and movements. A03b should confirm whether refunds go through it.
