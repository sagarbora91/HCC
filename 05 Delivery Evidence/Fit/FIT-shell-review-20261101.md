## 6. Contract points the implementation shows to be wrong or unclear (for the coordinator to amend)

1. **ModalFrame (§3/§4).** `ModalHost` already supplies the scrolling `.modal-body`, so ModalFrame inside it duplicates the wrapper. Say plainly: ModalFrame is for stand-alone dialogs only and must then render the `.modal` shell itself. Name the existing stand-alone dialogs (`DayPack`, `ServerDayPack`, `guestid-ui`) and say whether they get the framed behaviour (fit-people owns `exports`? not listed in §7; assign an owner).
2. **Phone reach of modal CSS (§1/§3).** "`.modal`" is shared between phone sheets and desktop dialogs, and some phone paths open desktop-style dialogs (Day pack). The contract should require the new class (`.fit-modal`) rather than `.modal:not(.m-sheet)`.
