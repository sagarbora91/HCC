## 2. The interface all lanes build to (do not change it; say so in the DONE file if it cannot work)

**Folders on the hotel PC**
- `{app}` = `C:\Program Files\HCC` : `Server\` (publish output, `Server\web\index.html`), `Operations\` (all `.ps1`), `ImportTemplates\`, `ClientKit\`, `SqlSetupMedia\` (only during install, deleted afterwards).
- `C:\ProgramData\HCC\` : `Setup\` (answer file while installing, `install-state.json`), `Logs\install-<yyyyMMdd-HHmmss>.log`, `Keys\` (existing convention), `certs\HCC-Hotel-CA.cer` (public certificate only).

**Answer file** `C:\ProgramData\HCC\Setup\answers.json` (written by the wizard, read once by the orchestrator, deleted in `finally`):
```json
{ "mode": "Trial|Production", "hotelName": "", "serverName": "", "serverIps": ["192.168.1.10"],
  "httpsPort": 5443, "backupDirectory": "C:\\HCC-Backups", "ownerUserName": "", "ownerPassword": "",
  "sql": "InstallBundled|UseExisting", "caPfxPassword": "", "offlineCopyDirectory": "" }
```
`caPfxPassword` and `offlineCopyDirectory` are required in Production mode (DEC-087: CA private key and key copies leave the PC on USB) and unused in Trial mode.

**Orchestrator** `Operations\Install-HccServer.ps1 -AnswerFile <path> [-Resume] [-PlanOnly]` (lane `server`). It runs the existing scripts in the order `INSTALL.md` prescribes and records each finished step in `install-state.json`, so a failed install can be run again and continues at the failed step:
1. `Bootstrap-HccSql.ps1` (lane `sql`) 2. `Initialize-HccDatabase.ps1` 3. `New-HccCertificate.ps1 -UpdateConfig` 4. write / merge `appsettings.Production.json` and `hcc-ops.json` 5. `New-HccGuestIdKey.ps1`, `New-HccBackupKey.ps1` 6. `Hcc.Api.exe migrate` (as the elevated administrator, after steps 3–5, because Production start-up validation needs them) 7. `Install-HccService.ps1` and start 8. `Initialize-HccProperty.ps1` (hotel + first Owner over the loopback listener, then loopback closed) 9. `Register-HccBackupTasks.ps1` 10. `Set-HccEgress.ps1 -State Install` 11. `New-HccClientKit.ps1` (lane `client`) 12. health check: `https://<serverName>:<port>/` answers and the API reports the schema current.
Exit codes: `0` done; `2` restart of Windows needed, run again with `-Resume`; `1` failed (the log names the step). `-PlanOnly` prints the steps and changes nothing.

**Trial mode** (this wave's first deliverable): everything is created automatically so the owner can try the install on a spare PC: the hotel CA and server certificate are generated on the PC, the CA key is kept in an ACL'd PFX under `C:\ProgramData\HCC\Keys` with a generated password stored beside it under the same ACL, key offline copies are skipped, and the first sign-in page and the Start-menu entry say **TRIAL - not for real guest data**. A trial install can later be turned into a production one only by the keys session (not built in this wave: say so in INSTALL.md).

**SQL bootstrap** `Operations\Bootstrap-HccSql.ps1 -Mode InstallBundled|UseExisting -MediaDir <dir> [-PlanOnly]` (lane `sql`): exit `0` instance `.\SQLEXPRESS` ready and reachable with Windows authentication by the installing administrator; `2` restart needed; `1` failed.

**Client kit** `Operations\New-HccClientKit.ps1 -ServerName <name> -Port <n> -HotelName <text> -CaCer <path> -OutDir {app}\ClientKit` (lane `client`) writes into `ClientKit\`: `HCC-Client-Setup-<ver>.exe` (shipped inside the server installer), `HCC-Hotel-CA.cer` (public), `hcc-client.json` `{ "serverUrl": "https://<name>:<port>/", "hotelName": "" , "caSha256": "" }`, `READ-ME.txt`. The owner copies this folder to a USB stick and runs the setup on each client PC. The client setup reads the `.cer` and `.json` **from its own folder**; if they are missing it asks for the server address and the `.cer` file.

**Build** `installer\Build-Installer.ps1 [-Version x.y.z] [-SqlPayloadDir <dir>] [-SkipSqlPayload] [-OutDir E:\Projects\HCC\Installers] [-DryRun]` (lane `build`) produces `HCC-Server-Setup-<ver>-x64.exe`, `HCC-Client-Setup-<ver>.exe` (also standalone) and `SHA256SUMS.txt`.
