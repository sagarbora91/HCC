## 1. One report = one definition → one selector → three renderers

```
ReportDefinition (catalogue record, static)          params (bound + validated by date class)
          │                                                        │
          └──────────► DataSelector(def, params, caller) ──► ReportResult (rows, totals, flags, about)
                                                                     │  permission filter + money masking + guest masking (§3)
                                                                     │  computed columns (§6)
                                     ┌───────────────────────────────┼───────────────────────────────┐
                                  screen                           Excel                         PDF / print
                         (React table / phone cards)      (xlsx.ts / OpenXmlExporter)      (PrintModel → HTML print | PDF bytes)
```

- The **selector runs once** per request; the three renderers take the same **masked** `ReportResult`. Figures are identical by construction; the golden harness proves it (§9).
- A renderer never queries, never re-totals, never re-rounds. Totals are rows in the result (`kind:'total'`).
- Money is integer paise in the result; screen formats with `money()`, Excel writes `{amt}` / `XlsxMoney` (`#,##0.00`, number), PDF formats with the same `rupees()` text as screen.

## 2. Catalogue registry

- One registry per side: prototype `src/domain/reports/catalogue.ts` (`registerReport(def)`), server `Hcc.Reporting` `ReportCatalogue` (DI: `services.AddReport<TDef>()`). Same ids, same column keys, same flags; a cross-check test reads both lists from a shared JSON (`03 Prototype/src/domain/reports/catalogue.json` generated by `tools/rpt-catalogue.mjs`, copied into `Hcc.Reporting.Tests`).
- A definition carries: `id` (`rpt.<area>.<slug>`, never renamed), `title`, `area`, `priority`, `status`, `moneyFlag`, `moneyGate` (PERM code), `viewPerms` (any-of), `deskPerms` (rule V.5), `exportPerm` (default PERM-RPT-003; file products keep their own, e.g. ACC-006), `dateClass`, `params`, `columns` (key, label, type, money y/n, masked kind, computed?), `grouping` / `sort` / `totals`, `dateBasis` text, `formats` (`screen|xlsx|pdf|csv|zip|xml`), `phone` (`yes|summary|no`), `layout` (`table` default | `document` for legal layouts), `legacyIds`.
- The catalogue's §2 status column must equal the registry: a test (`stream-rpt-catalogue.mjs`) parses §2 and fails on a mismatch (integrator updates statuses from code).

## 3. Parameters, permissions, money, masking

**3.1 Parameter binding.** Each param has `type` (`date`, `range`, `month`, `fy`, `enum`, `text`, `bool`, `party`, `room`, `user`) and the date params take a **date class** from catalogue §1.4 (D-DAY, D-S, D-B, D-F, D-M, D-FY, D-ASOF, D-NOW, D-FWD). `bindParams(def, raw, ctx)` fills defaults from the business date (prototype `s.clock`, server business-date service — never wall clock), refuses From > To, future dates (except D-FWD) and over-max ranges with `VALIDATION`, and sets `legacy` when the range reaches a legacy FY. Paging: 100 rows / phone 50 on screen; Excel / PDF up to 50,000 rows, above → `RPT_TOO_LARGE` ("narrow the range").

**3.2 Permission filter (rule V).** View = any of `viewPerms` (+ `deskPerms`). Print = view. Excel / PDF / CSV = view **and** `exportPerm`. Scheduled runs evaluate as the schedule owner's role. Server enforces through `IAccessPolicy.RequireAsync`; prototype through `can()`.

**3.3 Money (rule M).** If the caller lacks `moneyGate`: money columns are **removed** (not blanked), and computed / total columns depending on them go too; if no column remains → `FORBIDDEN`. Housekeeping / Maintenance / Stock-only roles never pass a money gate (DEC-061) — enforced by a static check that no such role holds any gate named in the catalogue (test).

**3.4 Masking (§1.6).** Column `mask` kinds: `guestName` (`J•••` without billing / reservations), `idNumber` (`XXXX-XXXX-1234` always, every format; a file never holds the full number), `bankAccount` (masked on screen and PDF, full only in a bank file product). Masking happens in the selector output stage, before any renderer.

## 4. Renderers

**4.1 Screen.** Prototype `features/reports/ReportView.tsx` (hub lane): table on desktop with `usePaged`, cards on phone (`phone:'yes'`), tiles + top rows for `summary`. Server-backed screens fetch `GET /reports/{id}?…` (JSON `ReportResult`).

**4.2 Excel.** One sheet per report + an **About** sheet (parameters, date basis, run time IST, user, `provisional`). Header bold, frozen; money numbers; dates as dates; totals as values; formulas only for computed columns (§6). File name `<property code>-<report id>-<from>-<to>.xlsx`. Prototype `xlsx.ts`, server `OpenXmlExporter`.

**4.3 PDF or print.** The renderer builds a **PrintModel** (header block: property, report title, parameters, run time, user; body tables split into pages; footer "Page x of y" + date basis; A4, landscape when > 8 columns; `document` layouts own their model). Two back-ends:
- **Print (both sides, day one):** PrintModel → HTML (`printHtml(model)`) → `native.ts` `printDocument` (Android printer plugin / browser print → "Save as PDF").
- **PDF bytes (server, for export, schedules and goldens):** `MinimalPdfWriter` in `Hcc.Reporting` — in-repo, no NuGet, PDF 1.4, standard Helvetica / Helvetica-Bold (WinAnsi, English only per A19; `₹` printed as `Rs.`), text + rules only, deterministic (fixed `CreationDate` from the run record, no random ids) so golden text extraction is stable. PDFsharp / ETP `PdfReportExporter` may replace it later behind `IReportRenderer` (§10).
- Prototype PDF = print model; golden harness checks the PrintModel text, the server checks PDF text + page count (`tools/pdf-drift.mjs`, not bytes).

**4.4 CSV / ZIP / XML** are extra formats on the same result; CSV cells starting `= + - @` neutralised (`CsvFormula.Neutralise` / prototype `csv.ts`). Tally XML stays its own product (ACC-006, 31-day file limit) listed in the catalogue with `formats:['xml']`.

## 5. Scheduled runs, print / export log

- `rpt.schedule` (server table, 4400s): id, report id, params JSON (relative date tokens like `yesterday`, `month-to-date`), format, cron-like cadence (daily / weekly day / monthly day + time IST), owner principal, recipients (internal user ids; money reports only to Owner / Manager / Accountant — §1.9), enabled, last run.
- `rpt.run` (table): id, schedule id (nullable for manual), report id, params, caller, started / finished, status (`ok|failed|held`), row count, file ref, error. The **outbox worker** runs due schedules; delivery is an outbox message which the F5 egress gate **holds** while `net.*` is OFF (status `held`, visible in the hub and in `rpt.admin.scheduled-runs`). Files land in the documents store (LF `HccDocuments`) by ref, never inline in the main DB.
- `rpt.export_log` (table): id, at, user, report id, params hash + JSON, format (`print|xlsx|pdf|csv|xml|zip`), rows, file name, `provisional`. Every print and export writes one row (rule V.4). Prototype mirror slice `s.rptX` (optional, no SCHEMA bump) holds favourites, schedules, runs and the export log.

## 6. OP-13 computed-column hook

A column may declare `computed: { expr: string, deps: string[] }`. Evaluation goes through `ComputedColumnEngine` (prototype `computeColumns(result, def)`, server `IComputedColumnEngine`). **Today** the only engine is `FixedCodeEngine`: `expr` names a registered TypeScript / C# function (`'pct(occupied,sellable)'`, `'sub(gross,net)'`) — same results on both sides, integer paise, half away from zero. When OP-13's calculation engine arrives it registers as another `IComputedColumnEngine` and may also emit Excel formulas (the only place formulas are allowed). Money propagation: a computed column whose deps include a money column is a money column.

## 7. Moving the 62 built reports onto the renderer

- **Adapter first, rewrite never:** a built report becomes a definition whose selector wraps the existing domain function (`reportPack` tab, `rctReport`, `accPl`, `AgeingQueries`, …) and maps its output into `ReportResult`. No figures change; existing tests stay as they are.
- **Entry point switch** per report by the integrator: the old page button calls `openReport(id, params)`; the old per-page print / xlsx stays reachable until the golden passes (rollback rule). A report failing its golden stays on the old path and is listed in `RPT-DONE.md`.
- `ReportPack` tabs map 1:1 via `packTabSelector(tabId)` (metrics → a two-column table, table → rows, `derived` → computed columns).
