# Installing the Hotel Control Centre server (owner's guide)

This puts the HCC server on the hotel's Windows PC. Staff then open HCC in a browser at `https://<server>:5443/` (the server itself serves the web app, section 6c; no separate web server) or use the Android app, over the hotel Wi-Fi/LAN.
Nothing here is sent outside the hotel. Do the steps in order; each one says how to check it worked.
**Status:** Wave 1 scripts, hardened by the security review of 26 Oct 2026 (S3). They have been dry-run tested only (`-WhatIf`), not yet run on the hotel PC. Do the first install on the real PC with a spare hour, and keep a note of anything that differs.

**Words used:** *PowerShell (Admin)* = Start menu, type PowerShell, right-click, "Run as administrator". *The scripts folder* = `C:\Program Files\HCC\Operations` (the installer puts them there; only administrators can change files there, which the backup tasks rely on; from the source tree they are in `08 Production\deployment\windows`).

## 0. Before you start
- A Windows 10/11 PC that stays on, with a fixed address on the hotel network (ask your router/IT person to give it a "reservation" so it always gets the same number, for example `192.168.1.20`). Write the PC name and that number down.
- A second drive or folder for backups, ideally **not** the same disk as the data (for example `D:\HccBackups`, or a USB/NAS disk). Turn on **BitLocker** for that drive (Settings > Privacy & security > Device encryption / BitLocker; Windows Pro) so a stolen disk cannot be read.
- Two **keys** USB sticks with the same files (CA backup, guest ID key, backup key; DEC-087: one in the hotel safe, one off site with the owner) and, separately, the weekly **backup copy** disk. Never keep the keys on the backup disk.
- A **UPS (battery backup)** for the server PC, the Wi-Fi router and the network switch, big enough to carry the three of them for at least 30 minutes. A power cut then does not stop HCC, and Windows and SQL Server are never switched off in the middle of a write. Install the UPS maker's software and set it to shut Windows down cleanly when about 5 minutes of battery are left (section 8b). A printer that the front desk can reach (any printer the PC or the Android print service can use).
- You are a Windows administrator on the PC.
- **.NET 10 runtime (x64)**: the HCC server is published "framework-dependent", so the PC needs Microsoft's .NET 10 runtime for web servers. Download the **"ASP.NET Core Runtime 10.0.x - Windows Hosting Bundle"** from https://dotnet.microsoft.com/download/dotnet/10.0 and install it (it contains both the .NET Runtime and the ASP.NET Core Runtime; the IIS part it also installs is not used and does no harm). Alternatively install both the ".NET Runtime 10.0.x (x64)" and the "ASP.NET Core Runtime 10.0.x (x64)" installers. **Check:** PowerShell: `dotnet --list-runtimes` lists `Microsoft.NETCore.App 10.0.x` **and** `Microsoft.AspNetCore.App 10.0.x`. Without it the service cannot start (step 5); `Install-HccService.ps1` (step 3) refuses to install the service and says what is missing. Windows Update keeps 10.0.x patched if "Receive updates for other Microsoft products" is on.

## 1. Install SQL Server Express (the database)
1. Install **SQL Server 2025 Express** (free) with default settings, instance name `SQLEXPRESS`, Windows authentication. If ETP is already on this PC, the instance is already there: reuse it, HCC uses its own two databases, `Hcc` and `HccDocuments` (photos and scanned documents; see section 2), and never touches ETP's.
2. Install **SQL Server command-line utilities** (`sqlcmd`) if it is not there (the scripts use it).
3. Check: PowerShell: `sqlcmd -S .\SQLEXPRESS -E -C -Q "SELECT @@VERSION"` prints the version. (`-C` = trust the server's certificate: the current `sqlcmd` encrypts every connection and SQL Server Express only has a self-made certificate. The HCC scripts add `-C` by themselves when SQL Server is on this same PC - `.\SQLEXPRESS`, `localhost`, `127.0.0.1` or this PC's name - and never for SQL Server on another computer; see `TrustServerCertificate` in section 7.)

## 2. Windows account for HCC and the database
Simplest: let the service run as its built-in "virtual account" `NT SERVICE\HccServer` (no password to manage). Then, in PowerShell (Admin), in the scripts folder:
```
.\Initialize-HccDatabase.ps1 -ServiceAccount "NT SERVICE\HccServer" -BackupDirectory "D:\HccBackups" -GrantDrillRights
```
Add `-WhatIf` first to see what it will do. It creates two empty databases: `Hcc` (everything except the images) and `HccDocuments` (LF, owner ruling DEC-200: ID images, bill photos, deposit slips and compliance files, in a separate database with its own 50 GB SQL Server Express allowance; `-DocumentsDatabase ''` skips it on an old install), and:
- lets the HCC service **read, write and run** in those two databases only. The service is **not** the database owner: it cannot change tables or switch off the audit trail. Building and upgrading the tables (`Hcc.Api.exe migrate`, step 5) is done by **you**, the administrator, with your own Windows login, only at install and upgrade.
- lets the backup tasks (they run as the Windows SYSTEM account) take backups and run the weekly restore test.
- creates the backup folder as a **private** folder: only SYSTEM, Administrators, SQL Server and the backup account can open it (no other Windows user of this PC can copy the backups).
(If you prefer a dedicated Windows user such as `HOTELPC\svc-hcc`, create that user first, give its name here and in step 3. A dedicated backup user instead of SYSTEM: `-BackupAccount HOTELPC\svc-backup`, then use the same name in section 7.)

## 3. Install the server files and the service
1. Run the installer `HCC-Server-Setup-<version>.exe` and **keep the folder it suggests, `C:\Program Files\HCC`**. Every command in this guide, the backup tasks (section 7), the restore drill's guest ID check (`ServerDirectory` in `hcc-ops.json`) and the server's own safety backup before an upgrade (`Hcc:Operations:BackupScript` in `appsettings.Production.json`) use that folder; if you install somewhere else, change all of them yourself. The installer puts the programs in `C:\Program Files\HCC\Server`, the scripts in `C:\Program Files\HCC\Operations` and the import templates in `C:\Program Files\HCC\ImportTemplates`. It creates your two settings files **once**, from the samples next to them: `Server\appsettings.Production.json` (from `appsettings.Production.sample.json`) and `Operations\hcc-ops.json` (from `hcc-ops.sample.json`). If a file of that name is already there, it is left exactly as it is: an upgrade never overwrites your settings, and uninstalling never deletes them. (Without the installer: copy the published server files to `C:\Program Files\HCC\Server` and the scripts to `C:\Program Files\HCC\Operations`, and make the two settings files from the samples yourself.)
2. Open `C:\Program Files\HCC\Server\appsettings.Production.json` in Notepad **started as administrator** (Start menu, type Notepad, right-click, "Run as administrator", then File > Open; or type `notepad "C:\Program Files\HCC\Server\appsettings.Production.json"` in PowerShell (Admin)). Only an administrator can save files under `C:\Program Files`, and after step 3 only administrators, SYSTEM and the HCC service can even read this file. Check: `BackupDirectory` is your backup folder; `ServerName` is how you want the server to be called (for example `Hotel PC`). Leave the connection string as it is. `LoopbackHttpPort` is `5080` for now (needed for step 6 only; it is switched off automatically afterwards). **There are no passwords in this file, and there must never be.** (`TrustServerCertificate=True` is only for a developer's laptop; the server refuses to start in production if it is present. The sample's `Encrypt=Optional` is what lets the service connect to SQL Server Express on this same PC without trusting its self-made certificate; it is accepted only for a local instance.)
3. PowerShell (Admin), scripts folder:
```
.\Install-HccService.ps1            # add -WhatIf first to preview; add -ServiceAccount HOTELPC\svc-hcc for a dedicated user
```
It creates the Windows service "Hotel Control Centre server" (starts automatically, restarts itself after a crash), opens port 5443 for the hotel network only (Private/Domain networks), makes `appsettings.Production.json` readable only by SYSTEM, Administrators and the HCC service, and registers the Windows Event Log source **HCC** that the server and the backups write their alerts to (section 7b; the installer registers it too). Do not start it yet.

## 4. Secure connection (HTTPS certificate)
Browsers and Android refuse plain HTTP logins on a network, so the server uses HTTPS with the hotel's own certificate authority (CA). Plug in the keys USB stick (here `E:`):
```
.\New-HccCertificate.ps1 -ServerName "HOTELPC" -DnsName "hotelpc.local" -IpAddress "192.168.1.20" -CaPfxPath "E:\HCC-Hotel-CA.pfx" -UpdateConfig "C:\Program Files\HCC\Server\appsettings.Production.json"
```
Use your real PC name and IP address (add `-WhatIf` first). What it does:
- The hotel CA can **only** vouch for this server's names and addresses (a "name constraint"): even if someone stole it, it could not fake a bank or Gmail in Chrome or Windows on your devices (install it only on the hotel's own devices). If the PC's address may change within your network, add `-PermittedNetwork 192.168.1.0/24`.
- It asks for a password for the CA backup file and writes the CA's private key **only** to `E:\HCC-Hotel-CA.pfx`; the key is then **removed from this PC**. Put the stick and the password in the safe: you need them once a year to renew (4b). If the export fails, the script undoes everything.
- The server certificate is valid for **397 days** and its key cannot be copied off the PC.
- It writes the certificate thumbprint and `AllowedHosts` (the names and addresses the server answers to) into the settings file.
You now have `certs\HCC-Hotel-CA.cer`: this is the file you install on every phone, tablet and PC (section "Phones and tablets" below). If the hotel already owns a proper certificate use `-ImportPfx file.pfx` instead.

### 4b. Renewing the server certificate (once a year)
Put a reminder in the calendar about 11 months after step 4 (the script prints the expiry date). With the keys stick plugged in, PowerShell (Admin), scripts folder:
```
.\New-HccCertificate.ps1 -RenewServer -CaPfx "E:\HCC-Hotel-CA.pfx" -ServerName "HOTELPC" -DnsName "hotelpc.local" -IpAddress "192.168.1.20" -UpdateConfig "C:\Program Files\HCC\Server\appsettings.Production.json"
Restart-Service HccServer
```
It loads the CA (its key cannot be copied while it is on the PC), issues a new server certificate, removes the CA from the PC again and updates the thumbprint. Phones, tablets and the APK need **nothing**: they trust the CA, not the server certificate. Afterwards delete the old server certificate in `certlm.msc` > Personal > Certificates (the one with the earlier expiry date).

## 5. Build the tables and start the server
PowerShell (Admin) - this is the "migration" step and must be run by you (the administrator), not by the service:
```
cd "C:\Program Files\HCC\Server"
$env:ASPNETCORE_ENVIRONMENT="Production"
.\Hcc.Api.exe migrate
Start-Service HccServer
```
`migrate` builds the tables of **both** databases, in this order: `Hcc` (on an upgrade it first takes a safety backup through the backup script and refuses to continue if that fails), then `HccDocuments` (its own safety backup when it already holds documents), then it **moves** the images that an older version kept inside `Hcc` into `HccDocuments` (in batches of 50; safe to run again, a second run moves nothing; it prints `Documents move: moved N row(s); remaining in Hcc 0`). Connection: `Hcc:Sql:DocumentsConnectionString` in `appsettings.Production.json`; empty means the same login and server with the database name `<name>Documents`.
The other two commands (PowerShell (Admin), same folder, `$env:ASPNETCORE_ENVIRONMENT="Production"`): `.\Hcc.Api.exe check-documents` counts references in `Hcc` whose image is missing in `HccDocuments` ("dangling") and images nobody refers to ("orphans"); `.\Hcc.Api.exe sweep-documents` removes orphans older than 24 hours (the server also does this every night at 03:30).
The server checks this itself: while the database is behind the installed version (`migrate` not run yet), every API address answers "503 unavailable" and the health page says "Database schema is behind this build: run `Hcc.Api migrate` (applied N of M)". Run `migrate`; within 10 seconds the server serves again (no restart needed).
**Check:** open a browser on the server PC: `http://127.0.0.1:5080/api/v1/system/health` should show `"status":"ok"`, the database name `Hcc` and a schema version (with the documents database: `HccDocuments` and its own, smaller version number, for example `Hcc 4674 / HccDocuments 0002`) (this plain address only works until step 6 is done). From another device on the Wi-Fi: `https://192.168.1.20:5443/api/v1/system/health` (works without a warning only after the CA certificate is installed, see below).
If it does not start: Event Viewer > Windows Logs > Application, source ".NET Runtime" (a settings problem at start-up: the message lists exactly which setting is wrong) or source "HCC" (section 7b).

## 6. Set up the hotel and the first Owner (once)
HCC needs to know your hotel and needs its first Owner account. One script does both, in one step. It works **only on the server PC itself** and **only on a new, empty installation**: once the hotel exists, it refuses to run again (nothing is changed).
PowerShell (Admin), scripts folder (replace the values in quotes with yours):
```
.\Initialize-HccProperty.ps1 -HotelName "Your Hotel Name" -Address "Street, City, PIN" -Gstin "27ABCDE1234F1Z5" -OwnerLogin "owner" -OwnerDisplayName "Your Name"
```
- It asks for the Owner password twice (12 or more characters; it is not shown on screen and not saved in the PowerShell history).
- You may leave out `-Gstin` to finish the setup, but **a valid hotel GSTIN (with its correct check character) is required before the first tax invoice**: the server refuses to issue invoices without it. Set or correct it later in Master configuration > Property and branding > GSTIN on documents. A Maharashtra GSTIN starts with 27; the script refuses one from another state.
- Already filled in for you (add the option only to change it): state `-State "Maharashtra"`, time zone `-TimeZone "Asia/Kolkata"`, check-in `-CheckInTime "14:00"`, checkout `-CheckOutTime "11:00"`, business date `-BusinessDate` = today (write it as `2026-11-01` if you start on another day).
- Add `-WhatIf` first to see what it will send (the password is shown as `********`, nothing is sent).
- When it succeeds it **switches off the plain-HTTP setup address** (`LoopbackHttpPort` = 0 in the settings file) and restarts the service. From then on the server PC uses `https://localhost:5443/` like everyone else. (The setup address never accepted sign-ins; it served only setup, health and discovery.)

It answers "Hotel '...' is set up. Sign in as 'owner' ...". Now sign in from the app as `owner` with that password, then add staff in Admin > Users. The hotel name, address, GSTIN and check-in/checkout times are also in Master configuration, where the Owner can change them later. Rooms, rates, staff, opening balances and the other master data are loaded in step 6d.
**Check:** `https://localhost:5443/api/v1/system/health` in a browser on the server PC shows ok, and `appsettings.Production.json` shows `"LoopbackHttpPort": 0`.
(No SQL commands are needed any more. On an older installation where the hotel row was already typed in by hand but no Owner exists, the earlier `auth/bootstrap-owner` call still works from the server PC itself; it is refused through any proxy.)

## 6b. Guest ID key (once, before the first check-in)
HCC stores guest ID numbers (Aadhaar, passport, ...) encrypted. The key is made on this PC and kept only in the settings file (never in git, never in the database or its backups). **Without this step check-in with an ID number is refused** with "ID storage is not set up on the server" (names, phones and the last 4 digits still work, and the rest of the app keeps working).
Plug in the keys USB stick and, in PowerShell (Admin), scripts folder:
```
.\New-HccGuestIdKey.ps1 -OfflineCopyPath "E:\HCC-guest-id-key-2026-10.txt"        # add -WhatIf first to preview; E: is the USB stick
Restart-Service HccServer
```
- It makes a random key, wraps it with Windows DPAPI for this PC (`dpapi-machine:`), writes it into `appsettings.Production.json` (`Hcc:GuestIdKeys`) and limits that file to Administrators, SYSTEM and the HCC service. The key is never printed. It refuses to run again once a key exists (replacing it would make stored numbers unreadable); the yearly change is `-Rotate -KeyId 2027-10` (steps in `src\Hcc.Application\GuestIds\README.md`, "Key rotation").
- **What the server checks at every start (Production):** a plain (unencrypted) key or `AllowPlainKeys` is refused; a machine-wide key is accepted only because the script also writes `AllowMachineScope: true`, and only while the settings file stays readable by SYSTEM, Administrators and the service alone (if someone widens the file's permissions, the service refuses to start and the event log shows the `icacls` command that fixes it); `Required: true` means the service also refuses to start if the key is ever removed. With a dedicated service user you can instead make a key bound to that user: run the script as that user (`runas /user:HOTELPC\svc-hcc powershell`) with `-Scope User`.
- **The USB file is the offline copy: copy it to the second keys stick (DEC-087), keep one stick in the safe and one off site, never e-mail it, never leave it on this PC.** A DPAPI key only opens on this PC and this Windows installation. If the PC is replaced or Windows reinstalled, or the settings file is lost, every stored ID number is unreadable (last 4 digits stay) unless you have that copy. **To put the key back** (replacement PC, section 7b), before the service starts:
```
.\New-HccGuestIdKey.ps1 -ImportOfflineCopy "E:\HCC-guest-id-key-2026-10.txt"      # add -WhatIf first; E: is a keys USB stick
```
  It reads the key and its id from the file, wraps it with DPAPI for this PC, writes it into `appsettings.Production.json` exactly as above (Required, AllowMachineScope, file permissions) and checks that it opens here; the key is never printed. Run it once per guest ID key file on the stick (after a yearly rotation: the newest key first, then any older key that still has ID numbers; an older one is added next to the current key, `-MakeCurrent` would make it current). It refuses the backup key's file and refuses to replace a key id that is already in the settings file: if that entry was copied from the old PC (it cannot be opened here) run it again with `-Force`, which warns and keeps the old file as `.before-guestid-key`. After the first successful check-in delete `appsettings.Production.json.before-guestid-key` (the script's safety copy).
- **Check that stored ID numbers open:** in the server folder, `.\Hcc.Api.exe verify-guest-id` (PowerShell (Admin), `$env:ASPNETCORE_ENVIRONMENT="Production"` as in step 5) opens the newest stored ID number per key with this PC's key and prints one line, never the number: `Guest ID check: OK (1 ID opened)`, `Guest ID check: no guest IDs to check` (nothing stored yet) or `Guest ID check: FAILED - ...` with what is missing (for example "sealed with key '2026-10', which is not installed on this server": import that key's offline copy). The weekly restore drill runs the same check on the restored copy (section 7).
- Optional: instead of the settings file you may put the same values in the service account's environment (`Hcc__GuestIdKeys__Current`, `Hcc__GuestIdKeys__Keys__2026-10`); use a `dpapi-user:` key there (the service's environment is not protected like the settings file).
**Check:** sign in, check a guest in with an ID number: it saves and shows `XXXX-XXXX-1234`. If the app says "ID storage is not set up on the server", this step was missed or the service was not restarted.

## 6c. Web app (browsers on the hotel network)
The server also serves the HCC web app itself, on the same address as the API, so staff just open `https://<server>:5443/` in a browser (no separate web server). The web app is one file, `index.html`, built from the source (`03 Prototype`): `npm run build:production` makes `03 Prototype\dist\production\index.html`.
1. Copy that file to **`C:\Program Files\HCC\Server\web\index.html`** on the server PC. This needs an administrator: in PowerShell (Admin) `Copy-Item "E:\index.html" "C:\Program Files\HCC\Server\web\index.html"` (with the file's real place), or copy it in Explorer and confirm the administrator prompt. The installer creates the `web` folder (create it if you copied the server files by hand); another place can be set with `Hcc:Hosting:WebRoot` in `appsettings.Production.json`.
2. No restart is needed, also not when you replace it later with a newer build: browsers fetch the new page the next time they open it (the page is never reused without asking the server first).
3. **Check:** `https://<server>:5443/` shows the HCC sign-in screen. If it says "The HCC web app is not installed on this server", the file is not in the `web` folder. That page never shows the folder (anyone on the network can open it); the server log has one warning naming the folder it looked in.
The page is sent with a strict content security policy (only its own script, only this server as a data source, no framing); every answer over HTTPS also tells the browser to use HTTPS only (HSTS), and API answers are never cached. The phones' APK has the web app built in and only needs the server address.

## 6d. Load your masters (rooms, rates, staff, opening balances, ...)
Before the first guest, HCC needs your rooms, room types and rates, the till float and your opening balances; staff, ledgers, guests, restaurant menu, departments, company clients, suppliers and stock items are loaded the same way. You fill CSV files once and one script loads them. Full column lists and rules: [`import-templates\README.md`](../import-templates/README.md) (installed in `C:\Program Files\HCC\ImportTemplates`).
1. **Fill the templates.** Copy the files you need from `C:\Program Files\HCC\ImportTemplates\templates` (source tree: `08 Production\deployment\import-templates\templates`) to a folder of your own, for example `D:\HccMasters`, keep the file names, and fill them in Excel (one item per row, first row unchanged; save as "CSV UTF-8"). The `samples` folder next to it shows filled-in fictional examples; never import the samples. No passwords, PINs or ID numbers in any file.
2. **Dry run.** PowerShell, scripts folder:
```
.\Import-HccMasters.ps1 -Folder "D:\HccMasters" -OpeningBalancesDate 2026-10-31 -DryRun
```
   It asks for the Owner sign-in name and password (not shown, not saved), uploads every file in the right order (room types before rooms, ledgers before opening balances, ...) and lets the server check every row; nothing is kept. `-OpeningBalancesDate` is the last day before HCC starts (the date of your trial balance); leave it out if you have no `opening-balances.csv`.
3. **Read the report.** For each file it prints the rows that are **REJECTED** with the row number, the column and what to fix, the warnings, and what will be created or changed. Fix the files in Excel and repeat step 2 until no row is rejected. On a new hotel a row marked "expected in a dry run" only waits for an earlier file of the same run (rooms wait for the room types) and goes through in step 4.
4. **Commit.** The same command without `-DryRun`:
```
.\Import-HccMasters.ps1 -Folder "D:\HccMasters" -OpeningBalancesDate 2026-10-31
```
   Each file is saved completely or not at all, in order; the script stops at the first file with a rejected row (fix it and run the script again: files already loaded show "unchanged" and are skipped). Opening balances and till cash are accepted only before the first business day is closed. Staff it creates cannot sign in yet: the script lists them, and you set each person's first password or PIN in Access control > Set credential.
5. **Verify.** The script ends with "Finished: ... committed, 0 file(s) with rejected rows". Sign in to the web app as the Owner on the server PC: the room grid shows every room (Ready) and Admin > Users lists the new users. In the same browser, `https://localhost:5443/api/v1/import/batches` lists every file as `Committed`, and `https://localhost:5443/api/v1/import/opening-balances` shows `"balanced":true` with your totals in paise. The first cashier shift on each till opens with the imported float. Stock items start at zero: count the store and floors in Stock > Count.
(`-WhatIf` lists the files and sends nothing. The script talks to `https://localhost:5443` on the server PC; from another PC use `-ServerUrl https://<server>:5443` (that PC needs the hotel CA, section 8). The Technical administrator may run the dry run; only the Owner can commit.)

## 7. Backups (do not skip)
Backups are **encrypted**: SQL Server Express cannot do that itself, so the backup script encrypts every checked backup with the hotel's backup key (AES-256, built into Windows, no extra software) and deletes the unencrypted file. A copied backup is useless without the key.
PowerShell (Admin), scripts folder, keys USB stick plugged in:
```
.\New-HccBackupKey.ps1 -OfflineCopyPath "E:\HCC-backup-key.txt"      # once: makes the backup key; the USB file is its offline copy (safe!)
if (-not (Test-Path hcc-ops.json)) { Copy-Item hcc-ops.sample.json hcc-ops.json }   # only if it is missing: the installer made it
notepad hcc-ops.json                             # check the folder names (Notepad from this PowerShell (Admin) can save it)
.\Backup-HccDatabase.ps1 -Type Full              # first full backup, now
.\Register-HccBackupTasks.ps1                    # schedules: full 02:30 daily, changes every 4 h from 04:30, restore test every Sunday 03:30
```
(`-WhatIf` on any of them shows the plan without doing it.)
- `hcc-ops.json` holds your folder names: the installer creates it once from `hcc-ops.sample.json` and never replaces it (also not on an upgrade), so never copy the sample over it (that would throw your settings away); the `Test-Path` line above copies the sample only when the file is missing (server files copied by hand). `Register-HccBackupTasks.ps1 -InstallScripts` copies the scripts **and** `hcc-ops.json` from the folder you run it from into `C:\Program Files\HCC\Operations`, replacing the ones there.
- The backup key lives in `C:\ProgramData\HCC\Keys` (only SYSTEM and Administrators can read it). With a dedicated backup user (section 2), add `-ReaderAccount HOTELPC\svc-backup` to `New-HccBackupKey.ps1` and `-RunAsUser HOTELPC\svc-backup` to `Register-HccBackupTasks.ps1`, and put `"BackupAccount": "HOTELPC\\svc-backup"` in `hcc-ops.json`.
- The scheduled tasks run the scripts **only** from `C:\Program Files\HCC\Operations`, and `Register-HccBackupTasks.ps1` refuses to register them if anyone other than administrators can change the scripts there (a task running as SYSTEM must never run a file a normal user could edit). If you ran the installer, the scripts are already there; otherwise add `-InstallScripts` (it copies them there and sets the permissions).
- `hcc-ops.json` has `"TrustServerCertificate": true`: the scripts' `sqlcmd` then trusts SQL Server's self-made certificate (needed for SQL Server Express on this PC; without it every backup fails with "The certificate chain was issued by an authority that is not trusted"). Leave it `true` while `SqlInstance` is on this PC. If you ever move the database to another computer, give that SQL Server a proper certificate and set it to `false` (if the setting is missing, the scripts trust only an instance on this PC).
- The differential ("changes") backups run at 04:30, 08:30, 12:30, 16:30, 20:30 and 00:30, so none starts together with the 02:30 full backup or the Sunday 03:30 restore test. `Register-HccBackupTasks.ps1` refuses times that collide (`-FullTime`, `-DifferentialStart`, `-DifferentialEveryHours`, `-DrillTime`).
- **Two databases (LF-docdb):** every run backs up `Hcc` first and `HccDocuments` second, each into its own file (`Hcc_FULL_...`, `HccDocuments_FULL_...`, all `.bak.hccenc`), each with its own retention, and records one row per database for System health. The weekly restore drill restores **both** into scratch copies (`HccDrill_<time>` and `HccDrill_<time>Documents`), checks both, and then checks that every image the main copy refers to exists in the documents copy (`Document reference check: 0 dangling reference(s)`). `hcc-ops.json` has `"DocumentsDatabase": "HccDocuments"` (empty = main only, for an old install).
- Backups are kept 30 days (never fewer than the 3 newest full ones). Only this database's files count (by their names, `Hcc_FULL_...`, `Hcc_DIFF_...`, `Hcc_PRE_...`): backups of another HCC database in the same folder are never counted or deleted. **Check:** `.bak.hccenc` files appear in the backup folder (no plain `.bak` files stay there); Task Scheduler > HCC folder lists three tasks.
- **Unencrypted file for a moment, and free space:** SQL Server Express cannot encrypt while it backs up, so each backup is first written as a normal `.bak` into the private backup folder; the script checks it, encrypts it and deletes the plain file straight away. If the backup, its check or the encryption fails, the script deletes that plain file before it reports the failure (the log says "The unencrypted file of this failed run was deleted"). So the backup drive needs free space for about **twice one full backup** while a backup runs. The restore drill (below) decrypts the backup into `DrillScratch` and restores a test copy there: keep about **twice the database's size** free on that drive; the decrypted copy is deleted at the end of every drill, also a failed one (a copy that cannot be deleted is named in the drill log). Only after a power cut or a killed task during a backup or a drill can a plain `.bak` stay behind: delete any `.bak` you find in the backup folder or in `DrillScratch` (only `.bak.hccenc` files belong there while `EncryptBackups` is `true`, the default).

**Run a restore drill now:** `.\Restore-HccDrill.ps1`. It checks and decrypts the newest backup into a throw-away copy, checks it for damage, compares record counts, **opens one stored guest ID number per key** in the copy with this PC's guest ID key, and deletes the copy (and the decrypted file), then says `DRILL PASSED` (log in the backup folder under `Logs`). A backup that was never restored is not a backup: the Sunday task repeats this every week; look at `Logs\drill-history.jsonl` or the latest `restore-drill_*.log` once a month.
- **Guest ID line (A07-03):** the guest ID key is never inside a backup, so the drill proves the restored ID numbers still open: the log shows `Guest ID check: OK (1 ID opened)` (never the number; `guestIdCheck: ok` in `drill-history.jsonl`). Before the first check-in with an ID number it says `Guest ID check: no guest IDs to check` and still passes. `Guest ID check: FAILED - ...` fails the drill: the key on this PC is missing or wrong, so install it from the offline copy (section 6b) before you ever need the backups. The check runs `Hcc.Api.exe verify-guest-id` from `C:\Program Files\HCC\Server` (`ServerDirectory` in `hcc-ops.json`) and refuses to run it if anyone other than administrators can change files there (the task runs as SYSTEM). `-SkipGuestIdCheck` leaves it out (logged as skipped; the drill then does not prove the IDs).

**Offline copy (weekly):** copy the backup folder's `.bak.hccenc` files to the backup USB disk (or another PC) and take it off site; a fire or theft takes the PC and the folder together. The files are encrypted, so the disk may travel, but keep the **keys** sticks (backup key, guest ID key, CA) in the safe and off site with the owner, never with the backup disk. **Restoring on a replacement PC:** section 7b.

## 7b. Replacement PC (the server PC died or was stolen, or Windows was reinstalled)
The backups hold the whole database but **none of the keys**: those come from a keys USB stick (DEC-087: the hotel safe or the owner's off-site copy). Without the backup key the backups cannot be opened; without the guest ID key every stored ID number stays unreadable (the last 4 digits still show). Do it with your technical person, in this order:
1. On the new PC: sections 0 to 3 as for a new installation (SQL Server, `Initialize-HccDatabase.ps1`, the installer and the service). **Do not start the service yet**, and do not run `Initialize-HccProperty.ps1` or the masters import (the hotel, its users and masters come back with the database).
2. Plug in a keys stick (here `E:`). Server certificate from the hotel CA, so the phones keep trusting the server: `.\New-HccCertificate.ps1 -RenewServer -CaPfx "E:\HCC-Hotel-CA.pfx" ...` exactly as in 4b, with the new PC's name and address (`-UpdateConfig` the settings file).
3. Keys, **before the service ever starts**:
```
.\New-HccBackupKey.ps1 -ImportOfflineCopy "E:\HCC-backup-key.txt"
.\New-HccGuestIdKey.ps1 -ImportOfflineCopy "E:\HCC-guest-id-key-2026-10.txt"      # each guest ID key file on the stick; newest first
```
   (`-WhatIf` first on both.) Never run `New-HccGuestIdKey.ps1` **without** `-ImportOfflineCopy` here: that makes a new key, and the stored numbers stay unreadable until the old key is imported as well.
4. `hcc-ops.json` as in section 7; copy the newest `.bak.hccenc` files from the backup USB disk into the backup folder and run `.\Restore-HccDrill.ps1`: it must end with `Guest ID check: OK (...)` and `DRILL PASSED`. A `Guest ID check: FAILED` line names the key that is missing: import it (step 3) and run the drill again.
5. Restore the newest backups into **both** the `Hcc` and the `HccDocuments` database with your technical person (it overwrites those databases, so there is deliberately no one-click script; the documents backup may be older than the main one), run `.\Hcc.Api.exe check-documents` (it lists references whose image is missing in the older documents backup and shows which main database the documents database was paired with), then as in step 5: `.\Hcc.Api.exe migrate`, `.\Hcc.Api.exe verify-guest-id` (must say `OK`, or `no guest IDs to check` for a hotel that never stored one), set `"LoopbackHttpPort": 0` in `appsettings.Production.json` (setup is not run on a restored hotel), then `Start-Service HccServer`.
6. `.\Register-HccBackupTasks.ps1` (section 7) and a full backup; then the final check list (section 9). Sign in as the Owner and open a guest who left an ID number: it shows `XXXX-XXXX-1234`, and Reveal ID shows the number.

## 7b. When something fails: Windows Event Log and System health (audit A09-05)
Nothing in HCC fails silently any more. Two places to look, both on the server side:
- **Windows Event Log**, source **HCC**: Event Viewer > Windows Logs > Application > "Filter Current Log..." > Event sources: HCC. `Install-HccService.ps1` (and the installer) register the source; without it nothing is written (check with `[System.Diagnostics.EventLog]::SourceExists("HCC")` in PowerShell (Admin), or run `.\Install-HccService.ps1 -EventSourceOnly`). The entries never contain guest data: only names of the parts that failed, event numbers, error types and SQL Server error numbers.

  | Event | Level | Meaning | What to do |
  |---|---|---|---|
  | 1001 | Warning | An outbox event failed once in a consumer (accounting vouchers, cleaning tasks, guest messages, OTA); it is retried, later events continue | Nothing yet; it becomes 1002 after 5 failures |
  | 1002 | Error | The event was **parked** after 5 failures: it is no longer retried; accounting periods with it cannot be locked | Admin & Setup > System health: fix the cause with your technical person, then **Retry** |
  | 1010 | Warning, then Error | A projector cannot work at all (usually SQL Server stopped): Warning at the first failure, Error after about a minute, then once an hour | Start SQL Server (`Get-Service MSSQL$SQLEXPRESS`) |
  | 1011 | Information | That projector works again | - |
  | 1020 | Error | The retention purge (old sessions, idempotency records, processed outbox events, old slip photos) failed; it tries again in 6 hours | Tell your technical person if it repeats |
  | 1030 | Error | A background part of the server crashed; the service stops and Windows restarts it | Tell your technical person |
  | 1040 / 1041 | Error / Warning | The database is behind this version (run `migrate`, section 5) / the schema check could not read the database | Section 5 |
  | 2001 | Error | A backup failed (reason: the script's message or the SQL Server error numbers) | Check the backup folder, the free disk space and SQL Server, then run `.\Backup-HccDatabase.ps1 -Type Full` |
  | 2002 | Error | The restore drill failed: the newest backup is not proven restorable | Run `.\Restore-HccDrill.ps1` and read its log |
  | 2003 | Warning | A backup worked but its result could not be recorded for System health | Re-run `Initialize-HccDatabase.ps1` (same options as section 2) |
- **Admin & Setup > System health** (Owner and Tech admin, desktop and phone): the parked events (which part, which event, how many attempts, when it last failed; never the guest data in it), **Retry** for each (the next poll tries it once more; if it fails again it is parked again at once), the last backup (kind, time, result, reason), the last good backup and the last restore drill, and whether the Event Log source is registered. The backup scripts record every run in the database for this (`plat.backup_run`); the backup account may only add rows there (`hcc_backup_reporter`; `migrate` adds the existing backup account, and re-running `Initialize-HccDatabase.ps1` adds it again).
- The accounting page shows a parked accounting event as "Accounting events stuck - see System health" (not "still being processed"): waiting does not help, a person must retry it.

## 8b. When the server is down (downtime procedure; owner decision DEC-081)
**Why paper.** Every phone, tablet and browser keeps an encrypted, read-only copy of today's data, but it deletes that copy and signs the user out **30 minutes** after the device last reached the server (a deliberate security choice: a lost tablet must not show guests). So after half an hour without the server, devices show nothing. The hotel therefore keeps three things ready, every day:
1. **The UPS** (section 0) on the server PC, router and switch. Test it once after installing: with the PC running, pull the UPS's mains plug and check that the server, Wi-Fi and the web app keep working, then plug it back in.
2. **A printed in-house list and arrivals list every morning.** After the business day has started (before the first check-in), the front desk opens **In-house stays** and presses **Print in-house list**, then opens **Arrivals & check-in** and presses **Print arrivals list** (desktop browser: the print dialog; Android app: the Android print service, or share the page and print it elsewhere). The lists show room, guest, booking number, number of guests, dates, phone (masked for roles that may not see it) and, for roles with billing access, the balance due or advance paid; the last column is empty for hand-written notes. Keep today's two sheets in a folder at the front desk, out of sight of guests; shred yesterday's, because they hold guest names and phone numbers.
3. **Paper to work on:** a numbered receipt pad (carbon copy), blank registration cards, and a pen at the desk.

**When the server stops answering**
1. Look for the obvious first: is the PC on, is the router on (UPS alarm?), does `https://<server>:5443/api/v1/system/health` answer from the PC itself? PowerShell (Admin): `Get-Service HccServer` should say `Running`; `Restart-Service HccServer` if it does not (give it two minutes). If SQL Server is the problem, section 5's Event Viewer hint lists the exact message. Do not restore a backup to fix an outage without calling your technical person.
2. **Work from the printed lists.** Rooms and guests in house come from the in-house list; expected guests from the arrivals list. Check in a guest on a paper registration card (name, phone, ID details as usual) and write the room number next to the guest on the arrivals list; the room stays allotted to that guest.
3. **Take payments on paper.** Write every payment in the numbered receipt pad: receipt number, date and time, room, guest, amount, cash / UPI / card and the staff member; keep the cash in the drawer and the UPI / card slips with the pad. Do not write tax invoices by hand: invoice numbers are given by the server and must stay in order, so give a numbered payment receipt now and issue the tax invoice once the server is back (DEC-090). For a guest who has already left, issue the invoice as soon as the server is back and send or hand it over the same way the guest was promised at checkout.
4. Housekeeping works from the in-house list; extra charges (laundry, restaurant) are written on the same pad with the room number.

**When the server is back**
1. Sign in again. Enter everything from paper **in the order it happened**: check-ins and check-outs first, then charges, then payments (reference = the paper receipt number). Do each paper line once and tick it off, so nothing is entered twice.
2. Do **not** close the business day until every paper receipt is entered and ticked. At the shift count the cash drawer as usual: a difference is handled by the usual cash-difference approval.
3. Issue the tax invoices for guests who left during the outage, staple the receipt pad pages and the printed lists to the day's papers, and tell the owner how long the outage lasted.

## 9. Final check list
- `https://<server>:5443/api/v1/system/health` shows ok, from a tablet, without a certificate warning.
- `https://<server>:5443/api/v1/system/discovery` shows the server name and version (this is also what the app uses to confirm it found HCC).
- `https://<server>:5443/` opens the sign-in screen (section 6c), and a check-in with an ID number saves (section 6b).
- `http://127.0.0.1:5080/` no longer answers (setup listener off, section 6).
- The backup folder holds `.bak.hccenc` files and the restore drill passed with a `Guest ID check: OK` (or, before the first ID number, `no guest IDs to check`) line; `icacls D:\HccBackups` lists only SYSTEM, Administrators, `NT SERVICE\MSSQL$SQLEXPRESS` (and your backup user).
- The two keys sticks (CA `.pfx`, guest ID key, backup key) are in the safe and off site with the owner (DEC-087); `certlm.msc` shows no "HCC Hotel CA" with a private key; a calendar reminder for 4b exists.
- Restart the PC: the service comes back by itself (give it two minutes).
- Masters loaded (section 6d): rooms, room types, rates, till float and opening balances committed with `Import-HccMasters.ps1`, no file with rejected rows.
- The UPS carries the server PC, router and switch (pull-the-plug test, section 8b); the front desk has printed an in-house list and an arrivals list from a real device and a printer; the receipt pad and blank registration cards are at the desk.
- The booking website is **off** (`"WebBooking": { "Enabled": false }` in `appsettings.Production.json`; section 10): `https://<server>:5443/api/v1/public/booking/quote?...` answers "not available".

## 10. Booking website on the internet (optional; only when the owner decides)
**The booking website stays off at go-live (owner decision DEC-085).** The booking routes (`/api/v1/public/booking/...`) answer "not available" until `Hcc:WebBooking:Enabled` is `true`, and the shipped `appsettings.Production.sample.json` has it `false`. Do not switch it on until the reverse proxy with a CAPTCHA in step 2 below is in place and tested; the server's own rate limit is not enough on its own against automated requests. Even then, **never port-forward 5443** (that would put staff sign-in and the whole staff API on the internet). The safe recipe:
1. In `appsettings.Production.json`: `"WebBooking": { "Enabled": true }` and, under `Hosting`, `"PublicPort": 5444`, `"PublicBindAddress": "127.0.0.1"`, `"KnownProxies": [ "127.0.0.1" ]`, and add the public site name (for example `book.yourhotel.in`) to `AllowedHosts`. Restart the service. Port 5444 then serves **only** the booking routes; everything else (sign-in, setup, staff API, the web app) answers "not found" there.
2. Run a reverse proxy on the same PC that terminates HTTPS with a real certificate for the public name (for example Caddy, which gets a free certificate itself) and forwards to `http://127.0.0.1:5444`, sending `X-Forwarded-For` and `X-Forwarded-Proto` (Caddy does by default). Put a CAPTCHA / rate limit in the proxy too. Only the proxy's port 443 is opened on the router.
3. How HCC treats it: forwarded headers are believed only on port 5444 and only from the addresses in `KnownProxies`, so the booking rate limit counts each real visitor separately; a request that did not arrive over HTTPS is refused; first-time setup and the first-Owner call are refused for any request carrying forwarding headers, on every port.
4. The server refuses to start if `PublicPort` is set on loopback without `KnownProxies`. A proxy on another machine: set `PublicBindAddress` to the PC's address (the listener then uses HTTPS with the server certificate) and list the proxy's address.

## Upgrading, uninstalling
1. Run the new installer: it stops the service, replaces the programs and the scripts, keeps your settings files (`appsettings.Production.json`, `hcc-ops.json`) exactly as they are and starts the service again.
2. **Only when upgrading from a version before 26 Oct 2026, and before `migrate`:** run `Initialize-HccDatabase.ps1` again (same options as step 2: it removes the old database-owner right of the service and protects the backup folder) and `New-HccBackupKey.ps1` (section 7). `migrate` first takes an encrypted safety backup; without the backup key that backup is refused and `migrate` stops (safely: nothing is changed). Check that `C:\Program Files\HCC\Operations\hcc-ops.json` exists (section 7).
3. Run `Hcc.Api.exe migrate` (new tables; as the administrator, see step 5); the safety backup is automatic. Until `migrate` has run, the server refuses to work and its health page says `Database schema is behind this build` (nothing is changed in the database meanwhile); it serves again by itself within 10 seconds after `migrate`. If `Hcc.Api.exe` says that .NET must be installed or updated, install the runtime as in section 0.
4. Only after an upgrade from before 26 Oct 2026: `Register-HccBackupTasks.ps1` (section 7), and set `AllowedHosts` (`New-HccCertificate.ps1 -RenewServer ... -UpdateConfig`).
5. **New settings are not added to your settings files.** The installer never changes `appsettings.Production.json` or `hcc-ops.json` once they exist, so a setting that a new version adds is not in them. It does replace the samples next to them with the new version's (`C:\Program Files\HCC\Server\appsettings.Production.sample.json`, `C:\Program Files\HCC\Operations\hcc-ops.sample.json`): compare each sample with your file (the version's release note lists what is new) and copy a new setting into your file by hand (Notepad as administrator). If a setting the new version requires is missing, the server does not start and Event Viewer (source ".NET Runtime", section 5) names it.

Uninstalling never deletes the database, the backups or your two settings files. To remove the service itself: `.\Install-HccService.ps1 -Uninstall`.

## Server setup program: what it does, upgrade, uninstall (technical notes)
`HCC-Server-Setup-<version>-x64.exe` asks the questions of sections 0-6b once (Trial or Production, hotel, this PC's name and address, backup folder, first Owner, SQL Server, and for Production the certificate password and the USB stick), then runs `Operations\Install-HccServer.ps1`, which does the steps for you in this order and records each finished step in `C:\ProgramData\HCC\Setup\install-state.json`: 1 SQL Server, 2 **register the HCC service (not started)**, 3 databases and logins, 4 hotel certificate (the CA is trusted on this PC), 5 settings files (a Trial install also gets the **TRIAL - not for real guest data** mark on the sign-in page), 6 guest ID key and backup key, 7 `Hcc.Api.exe migrate`, 8 give the service its certificate key and start it, 9 hotel and first Owner, 10 first backup and the backup tasks, 11 internet block for HCC, 12 client kit (`C:\Program Files\HCC\ClientKit`), 13 health check. The log is `C:\ProgramData\HCC\Logs\install-<date-time>.log` (passwords are never written to it).
- **Order when you do it by hand:** the service must be registered (section 3, step 3 `Install-HccService.ps1`) **before** the database step (section 2): SQL Server can only create the login `NT SERVICE\HccServer` after the service exists, and the key files can only be given to it then. Do section 3 first, then section 2, then section 4.
- **If it stops:** the message names the log. Fix the cause and run the setup again: it asks the questions again (passwords are never kept) and continues at the step that failed; finished steps are not repeated. If you type different answers than before, it refuses and names them. "Windows must restart" (exit code 3010): the setup is **not finished**; restart and run the setup again. A failed setup ends with exit code 1603. If no log appears at all, a Windows policy (execution policy `AllSigned`) may be blocking the script.
- **Trial** keeps the CA key in `C:\ProgramData\HCC\Keys` (password beside it, Administrators only) and the key copies in `C:\ProgramData\HCC\TrialKeyCopies`: they never leave the PC. The mode is recorded in `install-state.json` and in `appsettings.Production.json` (`Hcc:Install:Mode`, ignored by the server); an upgrade that finds neither stops and tells you to add it. A Trial install cannot be turned into a Production install by this setup (the keys session does that; not built yet).
- **Production** saves the CA key (`HCC-Hotel-CA-<date>.pfx`, protected by your certificate password) and the copies of the guest ID key and backup key on a removable USB stick. Put the stick and the password in the safe (section 0).
- **Backup folder:** a new or empty folder (or one that holds only HCC backups). The setup makes it private and that reaches everything inside, so it refuses a drive top, a user profile, Windows, Program Files, ProgramData and a folder with other files.
- **Network addresses:** only private addresses (10.x.x.x, 172.16-31.x.x, 192.168.x.x) that this PC really has. Port 5080 is reserved for the setup listener.
- **Upgrade:** run the new setup on the PC. It asks nothing, stops the service, replaces the programs and scripts, adds new settings to `appsettings.Production.json` and `hcc-ops.json` (it never changes a value you have, and never fills `AllowedHosts`, the certificate thumbprint, the setup-listener port, the server name, the backup folder or the guest ID keys from the sample: it warns if one is missing; a private copy `*.before-upgrade` is kept in `C:\ProgramData\HCC\Setup`), runs `migrate`, starts the service, refreshes the client kit and checks that HCC answers. If it fails, HCC stays stopped, the message names the backup folder and the log, and running the setup again retries. An older setup is refused over a newer install.
- **Uninstall** removes the service, the firewall rules, the scheduled tasks (so no more backups) and the program files (also the setup scripts: run the setup program again to repair or move HCC). It never removes SQL Server, the databases, the backups, the keys, the certificates or the two settings files, and it says so on screen, and names anything it could not remove. The hotel CA stays trusted on this PC.
- **Security notes:** the setup passes passwords inside PowerShell, never on a command line; do not run it on a PC where PowerShell module logging is switched on by policy (that logging records parameter values). The setup's helper script for creating private folders is written to the setup's own temporary folder and run as administrator (acceptable because that folder is private to the administrator running the setup).
- By hand: `Install-HccServer.ps1 -AnswerFile <file> [-Resume] [-PlanOnly]`; `-PlanOnly` lists the steps and changes nothing.
